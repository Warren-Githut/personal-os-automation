## Key Findings

### 1. Different abstraction layer — zero real overlap
OMH skills are **routing meta-skills** — they tell Hermes HOW to classify/route user intent. Warren skills are **domain executables** — they tell Hermes WHAT command to run. Same nouns, completely different purpose.

### 2. Skills are GENERATED from catalog source
92 skills rendered from `src/skills/catalog.py` + `render.py`. Template pattern: YAML frontmatter + 12 mandatory sections per skill. Not a format worth reproducing for Warren.

### 3. Three-way categorization

| Bucket | Count | Examples |
|--------|-------|----------|
| Overlap name only | ~20 | code-review, plan, morning-brief, data-analysis, skill-scout |
| New & useful | 4 | instinct-ledger, failure-signal-audit, decision-recall, workflow-learning |
| Engineering-only | ~68 | frontend, deploy, CI/CD, browser, IoT, accessibility-audit |

### 4. Trust Audit — 10/10 clean

| Dimension | Verdict |
|-----------|---------|
| Network/API calls | NONE (only urllib.parse for URL string parsing) |
| Telemetry/Analytics | NONE (all grep hits are catalog text, not SDK imports) |
| Runtime deps | ZERO (`dependencies = []`) |

| File writes | Local only (`~/.omh/`, `~/.hermes/`) |
